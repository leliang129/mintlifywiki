---
title: "Service"
description: "为一组 Pod 提供稳定的访问入口"
---

Pod 的 IP 会随着重建变化。Service 为一组 Pod 提供固定的虚拟 IP 和 DNS 名称,并做负载均衡。

## 工作原理

Service 通过 **Label Selector** 找到目标 Pod:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: nginx        # 匹配带 app=nginx 标签的 Pod
  ports:
    - port: 80        # Service 自身端口
      targetPort: 80  # Pod 内容器端口
```

集群内其他应用通过 `my-service` 这个 DNS 名称访问,不用关心后端 Pod 的具体 IP。

## 常用类型

| 类型 | 用途 |
| ---- | ---- |
| `ClusterIP` | 默认,仅集群内部访问 |
| `NodePort` | 通过每个节点的固定端口暴露到集群外 |
| `LoadBalancer` | 向云厂商申请一个外部负载均衡器 |
| `Headless` | 不做负载均衡,直接返回所有 Pod IP,用于有状态应用 |

<Tip>
  排查 Service 不通时,先用 `kubectl get endpoints my-service` 确认 selector 匹配到了 Pod。
</Tip>
