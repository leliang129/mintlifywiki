Terraform 用声明式配置管理云基础设施:你描述要什么,它负责创建并保持。本小节整理它的核心概念、工作流与落地要点。

## 核心概念速览

| 概念 | 说明 |
| ---- | ---- |
| Provider | 云平台插件(AWS、阿里云、Kubernetes 等) |
| Resource | 要管理的资源对象(主机、VPC、数据库) |
| State | 资源实际状态的记录文件,Terraform 的"账本" |
| Plan / Apply | 先预览变更,确认后再执行 |

## 标准工作流

```bash
terraform init      # 初始化,下载 Provider 插件
terraform plan      # 预览:会创建/修改/删除什么
terraform apply     # 执行变更
terraform destroy   # 销毁全部资源(练习环境用)
```

## 落地要点

- **State 远程化**:团队协作用远程后端(S3 + 锁),不要只存在本地
- **与 Ansible 分工**:Terraform 建资源(主机、网络、集群),[Ansible](/automation/ansible/overview) 配系统(软件、配置、服务)
- **模块化**:常用结构封装成 module,环境差异用变量区分
